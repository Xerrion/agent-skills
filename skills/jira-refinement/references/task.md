# Task

A Task describes technical, operational, administrative, or enabling work with a concrete deliverable.
State why the work matters, what it delivers, and how the team can check completion.
Do not invent a user story for this work. Technical Done When criteria can define the deliverable.
For an investigation recorded as a Task, use the Spike reference from the skill's selection table instead.

## Template

```markdown
## Purpose

<Why is this work needed?>

## Deliverable

<Concrete artifact or change to deliver>

## Done When

- <Verifiable completion condition>

## Notes

<Only relevant constraints, dependencies, or links>
```
