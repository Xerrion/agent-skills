# Spike / Investigation

A Spike produces knowledge or a decision, not necessarily production code.
Use a custom Spike type when available. Otherwise, use a Task with this structure.
Define the question, why it matters, the expected output, and a clear completion condition.
Select useful outputs, such as evidence, options, trade-offs, or a recommendation. Do not require every output for every investigation.

Include the agreed timebox. If none exists, ask for it as a material open question without blocking the draft.
Do not invent a timebox or declare the Spike ready without one.
Do not invent findings or recommendations before the investigation. Include those sections only when supported results exist.

## Template

```markdown
<What must this investigation learn or decide?>

## Context

<Why does this question need an answer?>

## Investigation

- <Bounded area or question to investigate>

## Expected Output

- <Required evidence, findings, comparison, recommendation, or decision>

## Done When

- <Observable condition that shows the investigation is complete>

## Timebox

<Agreed timebox, if available>

## Findings

<Supported results, only after investigation>

## Recommendation

<Evidence-based recommendation, only when available>
```
