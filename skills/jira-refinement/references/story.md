# Story

A Story describes what a user or stakeholder needs and why.
Use a supported persona and clear value. Do not invent a persona to disguise technical work as a Story.
Acceptance criteria describe observable outcomes, including known failure cases. Use Given/When/Then where useful.
Do not prescribe implementation unless it is a genuine constraint. Keep other technical context in Notes.

## Template

```markdown
As a <known user/persona>
I want <goal>
So that <supported value/outcome>

## Context

<Why is this needed? What problem does it address?>

## Acceptance Criteria

- <Observable and testable outcome>
- <Known failure case, when relevant>

## Notes

<Relevant constraints, links, designs, dependencies, or technical context>
```
