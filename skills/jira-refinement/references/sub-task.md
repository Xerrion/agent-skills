# Sub-task

A Sub-task is one small execution step belonging to a parent issue.
Ask for the parent if the context names none. Reference its key or link when available. Never invent one.

Never copy the parent's context, description, or acceptance criteria, even in Notes.
When rewriting, remove repeated parent content from the draft. The parent remains the source for that information.
Keep only the specific work, a small Done When list, optional local notes, and the parent reference.
Done When checks only this step, not the whole parent's outcome.

## Template

```markdown
<Specific piece of execution work>

Parent: <Known parent key or link>

## Done When

- <Completion condition for this step>

## Notes

<Only local context needed to execute this step>
```
